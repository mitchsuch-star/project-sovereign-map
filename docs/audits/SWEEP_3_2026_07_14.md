## Live-play evidence (fresh, France / 1805, real backend over HTTP + an engine probe)

Full log: `docs/audits/SWEEP_3_LIVE_EVIDENCE_2026_07_14.md`. The per-turn economy is
**mode-independent** (`calculate_turn_income`/`calculate_turn_upkeep` never call the LLM), so the
trajectory was captured in `LLM_MODE=mock` for determinism; the `LLM_MODE=anthropic` wire was
spot-checked green (fresh + multi-build end-turns both HTTP 200). Key organic beats:

- **EC-U1 non-regressive upkeep — confirmed live.** Over a real playthrough with enemy combat,
  **`upkeep_base` holds flat at 1512 across turns 0–6** while the army takes casualties — the
  establishment floor bills each surviving corps at its peak, so grinding it down no longer
  lowers the bill. **Net income only ever *declines*** (2939 → … → 2124), never rises: the
  "losing pays" symptom the Field Review found (net 1,702 → 3,250 while attriting) is gone. A
  destroyed corps still correctly drops out of the bill (T7 `army 189k→172k`, `upkeep 1512→1376`).
- **EC-U1 engine probe — the decisive counterfactual.** Grinding France's whole army 189,000 →
  103,950 (−85,050, a *losing* campaign): **WITH the fix net stays flat at +1652** (upkeep held
  1748); **WITHOUT it (establishment→0) net rises to +2584** (upkeep collapses to 816) — a **+932
  "losing pays" gain reproduced and then closed**.
- **EC-U2 conquest-free sink — confirmed live.** A homeland France builds a fortification in Paris
  and one in Lorraine (no conquest); after the 3-turn build they complete and the ledger shows a
  new **`Infrastructure: -80g`** line (2 structures × 40) from turn 3 on, and the turn-end economy
  message surfaces it — a real recurring drain the surplus can be spent into. Boot-safe: every
  nation reads `infrastructure 0` at turn 1 (the scenario authors no buildings), so the E1
  boot-solvency band (Austria +18) is untouched.
- **Ledger transparency held.** The visible economy lines still sum to Net (the SC-33 /
  `NET_GOLD_COMPONENTS` invariant), now including the Infrastructure component.

**Honest friction (pre-existing, not Phase-4 defects):** the treasury still grows over the run
(loose gold is *reduced* — non-regressive upkeep + the infra sink both bite — but a peacetime
homeland surplus can still bank if the player declines to invest); and a single non-reproducible
HTTP 500 was observed in the anthropic **response-encoding** path (a `set` with an unhashable
member) — it did not reproduce on a fresh turn or a repeat of the same multi-build turn, the mock
path with identical economy code is clean, and the Phase-4 diff adds only int fields, so it is a
pre-existing anthropic-only edge unrelated to this phase. Routed as a watch item, not a blocker.

### Headline — did Economy hit ≥6.5? **NO — 6.0, an honest half-point short.**

The build did real, correct work and the +1.0 is well-earned, but the target was missed and is not
rounded up (6.0 is within ±0.5 jitter of 6.5, but the reviewer's rationale is concrete, not
impressionistic):

- **EC-U1 closed the exact Sweep-2 "losing pays" regression** — the clean win, proven by the
  engine probe (−85,050 men: net flat +1652 **with** the fix vs a rise to +2584 **without**) and
  the live trajectory (`upkeep_base` flat at 1512 across turns 0–6 under combat).
- **EC-U2 added the first genuinely conquest-free gold sink** — infrastructure maintenance, its
  own signed Net component, live-verified 0→80g at turn 3, boot-safe.
- **Why it stays at 6.0:** the *absolute* loose-gold problem (the reason Economy sat at 5.0) is
  only lightly dented — the trajectory still climbs **treasury 0 → 16,333g in 7 turns**, and 80g
  of infra against a ~+2,300 net is small. The regression fix and the sink's *existence* are the
  value delivered; the sink's *magnitude* is not yet enough to make gold feel scarce.

oversized army* (absolute-size keyed), the one lever that bites the hegemon without touching the
