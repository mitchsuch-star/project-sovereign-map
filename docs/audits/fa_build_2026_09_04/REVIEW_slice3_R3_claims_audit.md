Method. ## Substantive findings

**S1. Slice 3 left an order-driven attack seam unread, and its own census pin mis-files it as an "answer arm."** `_handle_move_to_arrival` (`strategic.py`, the `attack_on_arrival` branch) executes `attack` under `_strategic_execution`, then unconditionally completes the order and returns `action: "attack_on_arrival"`, message "<marshal> arrives at <region> and attacks <enemy>!". Fed a refusal (`success: False`, no events) it does exactly what FA-14 filed — narrates a battle that never happened and consumes the order — and `attack_was_refused` is never consulted (measured on `16921a6b`, direct and through `process_strategic_orders`). `attack_on_arrival` is stamped by the typed out-of-range `attack <marshal>` route (`combat_executor.py:4862`), so this is a player path. The census docstring's "eleven order-driven + five answer/redirect" hides it by counting it, and the HOLD bombardment, among "two more answer arms." *Fix sketch:* in `_handle_move_to_arrival`, after the execute, `if attack_was_refused(result):` break the order with `refusal_reason(result)` and the refusal keys and no "attacks" copy; correct the census docstring to 13 order-driven + 3 answer arms; add the arrival arm to the direct-call pins (the `TestANonNavalRefusalReachesTheArmsThemselves` idiom). The cannon-fire redirect in `_handle_interrupt` is the same shape one step milder (a refused attack still abandons the order); worth the same read.

**S2. The "six green FA-N3 pins" claim is wrong by two, and the slice's own file does not pin the seam against the filed shape.** The literal filed fix (`if not result.get("success")` at the head of `_handle_combat_result`) reds four tests, all in `TestFAN3TheGloriousChargeIsNotADraw`, and nothing else across the 81 seam-family files; the slice-3 file stays 43/43 green under it. The sweep's `predicate/a` mutation keeps the events guard, so it reds no FA-N3 pin at all and is killed only by the slice's own `test_a_dict_with_no_verdict_at_all_is_not_a_refusal`. Nothing in `test_fa_slice3` would catch someone re-siting the refusal test at the seam in the filed form. *Fix sketch:* add one seam-level pin in the slice-3 file that calls `_handle_combat_result` with an event-only dict lacking `success` and asserts the victory arm (or point the `FA-14/a` sweep entry at the four cluster tests as well).
