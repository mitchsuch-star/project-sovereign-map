## 1. The shape of the road

There is **one** dispatch, and it is a flat `if/elif` chain, not a table:

| seam | file:line | what it keys on |
|---|---|---|
| main dispatch | `backend/commands/executor.py:2425`–`2586` (inside `_execute_one`) | `action` (**42** branches carrying **54** distinct keys), then `command_type` (**7**: the six general/auto types + `specific`) |
| `command_type` resolution | `backend/commands/executor.py:1592` — `command_type = command.get("type", "specific")` | the **inner** command dict's `type` key |
| sub-dispatch | `backend/commands/executor.py:3021` `_execute_specific`, branches `3044`–`3094` | `action` again, **15** branches |
| `meta_command` | `backend/commands/executor.py:1224` — **returns before the chain**, so `save`/`load` never reach the action economy | `raw_command` prefix |
| strategic interception | `backend/commands/executor.py:2405`–`2417` → `strategic_executor._execute_strategic_command` | `parsed_command["is_strategic"]` + `strategic_type` |

Six `command_type` branches exist and **all six are reachable** — measured in
`p6_auto.py` against the real mock parser on the 1805 boot world:

```
attack            -> type=general_attack
attack Mack       -> type=auto_assign_attack
bombard Swabia    -> type=auto_assign_bombardment
scout Lorraine    -> type=auto_assign_scout
retreat           -> type=general_retreat
defend            -> type=general_defensive
```

They are produced by `parser._determine_command_type`
(`backend/commands/parser.py:2173`–`2201`); the rule is *a resolved marshal
always means `specific`*.

### The side doors

`_execute_one` is not the only way into an executor.

* `POST /cancel_order` (`backend/main.py:5737`) calls
  `executor._execute_cancel(...)` **directly** and then re-implements the AP
  charge by hand (`world.use_action("cancel")` at `main.py:5776`) and the
  dialogue guard by hand (`main.py:5767`). This is the Strategic Ledger's
  Orders-tab cancel button. It is the only endpoint in `main.py` that calls an
  `_execute_*` method directly (grep over `backend/main.py`).
* `combat_executor.py:10190` and `movement_executor.py:1157` re-enter
  `_execute_specific` after auto-assigning a marshal (bombardment → a specific
  `attack`; auto-scout → a specific `scout`).

## 3. VALID_ACTIONS ↔ handlers: the four gaps

### 3.1 In `VALID_ACTIONS`, no dispatch key: `pursue`, `march`, `support`, `reinforce`

Proven by AST over `_execute_one`/`_execute_specific` (`p2_dispatch.py`) — none
of the four appears as a branch literal. **This is intentional and covered**:
`backend/ai/providers.py:248` `LLM_STRATEGIC_ACTION_REMAP` maps them to
`attack`/`move`, applied at `providers.py:347` inside
`build_parse_result_from_json`.

⚠ **The cover is one-sided.** That remap lives in the *live-LLM* JSON lift
only. The mock chain never emits them (string census over
`backend/ai/llm_client.py` — `pursue`/`march`/`support`/`reinforce` are absent
from every `"action"` assignment), so today nothing is broken. But a
hand-built command dict, a future producer, or a provider that bypasses
`build_parse_result_from_json` would land on `_execute_specific`'s `else:`
(`executor.py:3094`) and die as `"Unknown action: pursue"`. That is the exact
failure `repudiate_bargain` shipped with — and whose fix is documented in a
16-line comment at `executor.py:2508`–`2517`, inside the dispatch tuple it was
missing from.

Measured (`p3_parse.py`), the strategic upgrade works end to end:
`Ney, pursue Mack` → `action=attack, STRAT=PURSUE`;
`Ney, support Davout` → `action=move, STRAT=SUPPORT`.

### 3.2 Dispatch keys not in either set: `cheat`, `treasury`, `finances`, `meta_command`

All four are typed-reachable and functional (measured, `p3`). `treasury` and
`finances` are pure aliases folded into `economy` at `executor.py:2444`.

### 3.3 Handlers with no dispatch key — none are orphans

Every `_execute_*` method without a dispatch branch has a live internal caller
(grep per method): `_execute_glorious_charge` ← `combat_executor.py:5248`,
`8802`, `9349`; `_execute_build_watchtower` ← `economy_executor.py:2159`;
`_execute_make_amends_grievance_variant` ← `diplomatic_executor.py:1276`;
`_execute_hold_bombardment` ← `strategic.py:3059`;
`_execute_general_attack_combat` ← `combat_executor.py:9746`;
`_execute_bombardment` ← `combat_executor.py:6061`, `6552`,
`meta_executor.py:1882`; `_execute_post_objection` ← `meta_executor.py:2038`,
`2131`. **No dead executor.**

### 3.4 ⛔ Eight of the fifteen `_execute_specific` branches are structurally unreachable

`_execute_one` dispatches `drill` (`:2465`), `fortify` (`:2467`),
`unfortify` (`:2469`), `form_square` (`:2471`), `break_square` (`:2473`),
`stance_change` (`:2478`), `cheat` (`:2483`) and `debug` (`:2488`) **before**
it ever reaches `command_type == "specific"` (`:2565`). `_execute_specific`
carries its own branch for all eight (`:3077`–`:3091`), and none can be
entered.

Measured (`p8_shadow.py`, wrapping `_execute_specific` with a spy and driving
the real executor on the 1805 board with a literal marshal so no objection
intercepts):


The external callers do not rescue them: `combat_executor.py:10190` re-enters

**And an enforcement test asserts they must exist, for a reason that is false

`tests/test_enforcement_suite.py:465` `test_execute_specific_covers_tactical_actions`

## 4. THE DEFECTS

### 4.1 ⛔ P1 — `make_vassal` annexes a great power for free, and the only thing standing between a player and it is a keyword list in a `.gd` file

`vassalize <nation>` parses to `make_vassal`
(`backend/commands/parser.py:756`+ lists it; the mock chain emits it),
dispatches at `executor.py:2538` → `vassal_executor.py:122`
`_execute_make_vassal`. It is in **`free_actions`** (`executor.py:1273`), so it
costs **0 AP**; it is not in `ADMIN_ACTIONS`; it charges **no DP and no gold**.

The only gates are inside `backend/game_logic/vassal.py`:
`create_vassal_treaty:443` requires `VASSAL_MIN_STATES`
(`{WAR, OPEN_BORDERS, NON_AGGRESSION, DEFENSIVE_ALLIANCE, ALLIANCE}`);
`create_vassal_conquest:540` requires only `state == "WAR"`, not-already-a-vassal,
no release cooldown, and the WPS-B power cap. **No war score. No capital held.
No battle. No acceptance roll.**

Measured through the real `POST /command` route with the shipped 1805 world
swapped into `backend.main` (`p12_http.py`), **turn 1**:

```
BEFORE: turn=1 AP=4 DP=5 vassals=[Holland, KingdomOfItaly, Switzerland] FR_marshals=8
  'vassalize Austria' -> HTTP 200 success=True | Austria has been subjugated as a Puppet
                         vassal of France (loyalty: 20). Marshals assimilated: Mack,
                         ArchdukeCharles, ArchdukeJohn.
  'vassalize Britain' -> HTTP 200 success=True | ... Marshals assimilated: Moore.
  'vassalize Russia'  -> HTTP 200 success=True | ... Marshals assimilated: Kutuzov, Buxhowden.
AFTER : turn=1 AP=4 DP=5 vassals=[Austria, Britain, Holland, KingdomOfItaly, Russia,
                                  Switzerland] FR_marshals=14
states: {Austria: VASSAL, Britain: VASSAL, Russia: VASSAL}
```

Three sentences, on turn one, end the Third Coalition and take France's marshal
roster from 8 to 14. AP, DP and gold are all unmoved. Reproduced twice, before
and after the sibling's edit landed.

Per-nation reach on a fresh boot world (`p10_vassal.py`): succeeds against
**Austria, Britain, Russia** (WAR) and **Bavaria, Spain** (ALLIANCE); refused
against the other fourteen with *"requires WAR or OPEN_BORDERS+"*.

**What actually protects the shipped client — and why that is not enough.**
`godot-client/project-sovereign/scripts/main.gd:1602` calls
`_redirect_diplomatic_command` (`:1921`) before sending; it matches a
115-entry `DIPLO_FAMILY_KEYWORDS` list (`:1665`), which contains
`"vassalize"`, `"make vassal"` and `"subjugate"`, and returns without sending.
So a player typing into the terminal is stopped. But:

* the defence is **client-side copy**, in a `.gd` constant, with no backend
  counterpart. `tools/playtest_driver.py` posts straight to `/command`
  (`playtest_driver.py:2663`, `:3223`) and contains **zero** references to
  `vassalize`/`_redirect_diplomatic_command`/`DIPLO_FAMILY` — a scripted
  playtest that types it executes it;
* the golden corpus **asserts it succeeds**:
  `tests/data/parser_golden_corpus.json` id `vassalize-saxony`,
  `expected: {success: true, action: make_vassal}`, source *"CR-1 authored
  (action coverage gate)"* — a row added to satisfy a coverage gate, which now
  pins the verb as working;
* `make_vassal` is absent from the help text (measured: `_execute_help`'s body
  never contains `vassalize`, `make vassal` or `subjugate`).

### 4.2 ⛔ P2 — the Cabinet the guard points at has no chair for it

Of the **115** keywords `main.gd` intercepts, **exactly 3** name a backend
action the F1 Cabinet cannot produce — and they are the `make_vassal` family

conducted at the table, Sire — not by dispatch. Take your seat in the
Cabinet"* (`main.gd:1963`), opens F1, and finds only `propose_vassal` — a

sent down does not exist. The other 112 keywords all land somewhere.

### 4.3 P2 — `propose_white_peace` is click-only, and the typed sentence silently does something else

all** (measured, `p3`/`p4`). The wizard's own echo string is
`"propose white peace with " + nation` (`diplomacy_wizard.gd:766`), and that

```
  | "Sire, regarding the Peace Treaty proposal to Austria, I have prepared terms…"
wizard shape (flattened action+target_nation) white_peace_executor=True
```

(The wizard flattens its structured payload onto the request body —
`api_client.gd:151` `send_structured_command`.)

typed sentence does not *refuse* — it quietly executes a **different** action.
`main.gd`'s guard catches `"peace with"` for terminal input, so the divergence
is only reachable off-client; the risk is the same class as §4.1.
